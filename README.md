# SmartParking AI

Учебный проект: найти номер на кадре, прочитать его и решить, пускать машину или нет.

Сейчас готова **часть 1**. Она сама скачивает датасеты и складывает файлы так, чтобы следующие люди не разбирали архивы.

## Запуск

Команды из корня этой папки:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python src/prepare_data.py
```

Либо откройте `notebooks/01_data.ipynb` и выполните все ячейки. Ноутбук и скрипт делают одно и то же.

Первый полный запуск скачивает около **7 ГБ** и распаковывает их. Нужно примерно **15 ГБ** свободного места. Повторный запуск ничего не качает: если отчёт уже есть, скрипт сразу его показывает. Пересобрать графики и выборки: `python src/prepare_data.py --force`.

Проверить, что всё ставится, не скачивая train: `python src/prepare_data.py --quick`. На таком прогоне обучать модели нельзя.

## Что забрать следующим

| Кому | Куда смотреть |
|---|---|
| Детекция, часть 2 | `notebooks/02_detection.md`, затем `notebooks/02_detection.ipynb` |
| OCR, часть 3 | `notebooks/03_ocr.md`, затем `notebooks/03_ocr.ipynb` |
| Защита | `reports/part1_summary.json` и картинки в `reports/` |

В CSV колонка `text` — номер, колонка `image` — полный путь к картинке. Кропы номеров уже горизонтальные, поворачивать их не нужно. Номер на кадре детекции мелкий: при обучении YOLO сравните вход 640 и 960. Горизонтальное отражение номеров не включайте.

`train.csv` после `--quick` будет пустым. Для настоящей работы нужен запуск без `--quick`.

## Данные

В репозиторий сами фотографии не входят.

- Детекция: [Car_plate_detecting_dataset](https://huggingface.co/datasets/AY000554/Car_plate_detecting_dataset), разметка YOLO `class x y w h`.
- OCR: [Car_plate_OCR_dataset](https://huggingface.co/datasets/AY000554/Car_plate_OCR_dataset), номер записан в имени файла.

Официальные `train` / `val` / `test` сохраняются. Если один и тот же номер попал в разные выборки OCR, все его кадры собираются в одну. Точные копии файлов выкидываются.

Лицензия лежит в `license.txt` внутри скачанных архивов. В карточке датасета детекции в шапке указан Apache-2.0, в тексте — CC BY 4.0. Перед тем как выкладывать кадры, прочитайте этот файл.

## Часть 3

Часть 3 читает символы на уже вырезанном номере. Искать табличку на всей фотографии не нужно: это делает часть 2.

Фотографий в репозитории нет. Сначала из корня папки:

```powershell
python src/prepare_data.py
pip install -r requirements-ocr.txt
```

Дальше открыть `notebooks/03_ocr.md` и заполнять ячейки в `notebooks/03_ocr.ipynb`. Готовые кропы лежат в `data/processed/ocr/train.csv`, `val.csv` и `test.csv`. Колонка `text` — номер, колонка `image` — путь к картинке. Кропы горизонтальные, поворачивать их не нужно.

## Часть 4. Сайт-демонстрация

Один экран: загружаете фото или короткое видео — сайт находит номер
(детектор `weights/n640_best.pt`, YOLO11n), читает его (CRNN `weights/crnn_best.pt`),
проверяет формат и показывает решение: **пустить**, **отказать** или **ручная проверка**.
Шлагбаумом сайт не управляет.

```powershell
pip install -r requirements.txt        # включая streamlit
streamlit run app.py
```

Проверка пайплайна без сайта (одна фотография → рамка, текст, уверенность, решение, время):

```powershell
python demo_core.py кадр.jpg --whitelist A123BC777,K211PA69
python demo_core.py кадр.jpg --conf 0.85 --margin 0.07
```

- Белый список и история хранятся в SQLite: `data/processed/access.sqlite` (в git не попадает).
  Список редактируется прямо на сайте; русские буквы нормализуются в латиницу автоматически.
- Порог уверенности OCR (старт 0.85) и запас вокруг рамки (старт 7%) настраиваются в боковой панели.
- Видео решается по нескольким кадрам: побеждает текст с наибольшей суммой уверенностей,
  уверенность результата — средняя по проголосовавшим кадрам.
- Кадры для сценариев А/Б/В кладите в `data/demo/`, фактические результаты — в `data/demo/сценарии.md`.
- Детектор слабый и честно подписан на экране: «YOLO11n, 3 эпохи, не финальное сравнение».
