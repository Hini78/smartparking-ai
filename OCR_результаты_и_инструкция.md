# Часть 3. Чтение номера: результаты и инструкция по использованию

Проект SmartParking AI: часть 2 находит номер на кадре и вырезает его, **часть 3 читает вырезанный номер и возвращает строку**, часть 4 решает, пускать машину или нет. Этот документ про часть 3.

## 1. Что передаётся

| Файл | Назначение |
|---|---|
| `crnn_best.pt` | веса обученной CRNN (12,5 МБ), в файле хранятся алфавит, размер входа и параметры модели |
| `crnn_ocr.py` | всё, что нужно для использования: предобработка, модель, декодер, класс `CRNNReader` |
| `03_ocr.ipynb` | ноутбук, которым обучалась модель (Colab, GPU T4, около 12 минут на обучение) |
| `handoff.json`, `history.csv`, `val_comparison.csv`, картинки `examples_*.png` | метрики, история обучения и примеры ошибок |

Зависимости: `python 3.9+`, `torch`, `numpy`, `pillow`. Больше ничего не нужно, PaddleOCR для работы не требуется.

## 2. Как пользоваться

Положите `crnn_best.pt` и `crnn_ocr.py` рядом с вашим кодом:

```python
from crnn_ocr import CRNNReader

reader = CRNNReader("crnn_best.pt")          # сам выберет cuda, если она есть, иначе cpu

text = reader.read("crop.png")                # 'A123BC77'
text, conf = reader.read_with_conf(crop)      # ('A123BC77', 0.98), conf от 0 до 1
texts = reader.read_batch([crop1, crop2])     # список строк, быстрее, чем по одному
text = reader.read(cv2_crop, bgr=True)        # если кроп получен через cv2 (порядок каналов BGR)
```

Вход: путь к файлу, `PIL.Image` или `numpy`-массив с **уже вырезанным номером**. Искать табличку на всём кадре модель не умеет, это делает детектор из части 2.
Выход: строка латиницей без пробелов, алфавит `0123456789ABEKMHOPCTYX` (русские буквы, похожие на латинские, записываются латиницей: А→A, В→B, Е→E, К→K, М→M, Н→H, О→O, Р→P, С→C, Т→T, У→Y, Х→X).

## 3. Результаты

Метрики считаются одной функцией для обеих моделей. CER: доля лишних, пропущенных и заменённых символов (меньше лучше). Точность символов: доля символов эталона, прочитанных верно. Exact Match: доля номеров, прочитанных целиком верно.

| Модель | Выборка | CER | Точность символов | Exact Match |
|---|---|---|---|---|
| PaddleOCR (готовый, без дообучения, `en_PP-OCRv5_mobile_rec`) | val, 4368 кропов | 0,0477 | 95,3% | 72,0% |
| **CRNN (своя)** | val, 4368 кропов | **0,0059** | **99,4%** | **98,9%** |
| **CRNN (своя)** | test, 2849 кропов, один раз | **0,0078** | **99,3%** | **98,2%** |

Первая версия модели (до исправления разбиения, см. ниже) на том же test давала CER 0,0243 и Exact Match 84,8%.

## 4. Выводы

1. **Своя CRNN заметно лучше готового PaddleOCR на этих данных**: Exact Match 98,9% против 72,0% на val. PaddleOCR не знает формата российских номеров и часто путает или теряет символы, CRNN обучена именно на них.
2. **Ошибок 0/O и 8/B нет совсем**, тёмные и размытые кропы читаются не хуже остальных.
3. **Результат на test (98,2%) близок к val (98,9%)**, то есть модель не подогнана под val. Test считался один раз после выбора модели.
4. **Главная найденная проблема в данных.** В официальном разбиении датасета в train вообще не было номеров, начинающихся с букв X и Y, а в val их было около 740. Первая версия модели читала первую букву X/Y с точностью 0% и давала Exact Match около 84%. Мы перенесли 70% таких номеров из val в train (целиком по номерам, без утечки), test не трогали. Это подняло Exact Match до 98–99%.
5. **Оставшиеся ошибки** это редкие замены цифр (7↔8, 9↔7, 3↔5). Часть «ошибок» вызвана самим датасетом: у некоторых кропов метка не совпадает с написанным на табличке (например, на фото `У888УТ 197` в метке `B888AP99`). Поэтому 100% Exact Match на этом датасете недостижим.

## 5. Наставление по интеграции

- **Кропы должны быть похожими на обучающие.** Модель обучена на горизонтальных кропах, медиана около 238×51, номер занимает почти весь кроп. Не поворачивайте и не отражайте кроп (в номерах нельзя использовать горизонтальное отражение). Берите рамку детектора с небольшим запасом (порядка 5–10% с каждой стороны), но без большого количества фона вокруг.
- **Главный риск: кропы от детектора могут отличаться от кропов датасета** (другие отступы, наклон, масштаб). Мы этого не проверяли. Обязательно прогоните модель на кропах, которые реально выдаёт часть 2, и посчитайте качество на конечной цепочке «кадр → рамка → кроп → строка».
- **Используйте уверенность.** `read_with_conf` возвращает среднюю вероятность символов. Низкую уверенность (порог подберите на своих данных) не стоит считать надёжным чтением: лучше отдать на повторную попытку или ручную проверку, чем открыть шлагбаум по неверной строке.
- **Проверяйте формат результата.** Российский номер состоит из буквы, трёх цифр, двух букв и кода региона из 2–3 цифр: `^[ABEKMHOPCTYX]\d{3}[ABEKMHOPCTYX]{2}\d{2,3}$`. В обучающих данных все номера имеют длину 8 или 9 символов. Строку, не прошедшую такую проверку, лучше не принимать. Особые номера (спецтранспорт, иностранные) в этих данных не проверялись.
- **Не меняйте алфавит и размер входа.** Они зашиты в веса (изображение 32×160, 40 временных шагов). Загрузчик `CRNNReader` проверяет алфавит сам.
- **Сравнение со списком разрешённых номеров** лучше делать мягко: допускайте 1 ошибку в символе при сравнении только если это допустимо по политике доступа. Решение о допуске принимает часть 4, модель только читает.
- **Скорость.** Для работы в реальном времени используйте `read_batch` и GPU. На CPU модель тоже работает, она небольшая (около 3 млн параметров).
- **Безопасность файла весов.** `crnn_best.pt` загружается безопасным режимом `weights_only=True`, но всё равно берите его только из доверенного источника.

## 6. Ограничения и что не проверялось

- Не проверялись кропы от детектора из части 2 и качество на новых камерах, ночью, в дождь.
- Не проверялись иностранные и нестандартные номера, номера с двумя строками.
- Точное разбиение train/val изменено (перенос номеров X/Y), поэтому метрики на val нельзя сравнивать с моделью, обученной на официальном разбиении. Сравнение на test корректно: он один и тот же.
- Test считался дважды (для первой версии и для финальной). Выбор модели и гиперпараметров делался только по val.
- Часть меток датасета ошибочна, значит, метрики слегка занижены относительно реального качества.

## 7. Как переобучить

Откройте `03_ocr.ipynb` в Google Colab, включите GPU T4 (Среда выполнения → Сменить тип среды выполнения) и нажмите «Выполнить все». Ноутбук сам скачает датасет `AY000554/Car_plate_OCR_dataset` (около 1,2 ГБ), соберёт выборки, обучит CRNN (лучший вес по val CER, ранняя остановка), сравнит с PaddleOCR, один раз посчитает test и соберёт архив `smartparking_ocr_crnn.zip`. Для быстрой проверки поставьте `QUICK = True` в ячейке 0.
